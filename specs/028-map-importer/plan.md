## 2. Curation schema (FR-592 in the spec)
Wrong type, unknown member, empty `columns.key`, over-length list -> `invalid-curation` (member path); over 16 MiB before parsing (NFR-135). Key **lengths** are not schema errors: a territory or faction key, curated or generated, outside 1..256 code units fails `invalid-key` in the curation stage (FR-599), never `invalid-curation`.

## 3. Projection and insets (FR-600, FR-601, PD6)
`laea` reuses `core/projection.ts`; `equal-earth` is own code on the published constants. The **global** projection keeps meridian 0; each inset centres on its units' own lon/lat midpoint, which with `equal-earth` **is** its lon0 (PD6). Every view projects longitudes as `lon - lon0` wrapped into (-180, 180], never left unwrapped; `antimeridian-edge` per view: the main map refuses an unsplit antimeridian ring, an inset centred on it accepts it. Centre and frame take the selected units' raw outer+hole vertices exactly as 003b `build.ts` L57-61 (pre-normalisation: no step before projection). `frameFor` unchanged; inset rectangle = projected bbox + margin x main side, rounded outward, at (x, y); a seed lies in the first inset containing it, else the main view.

## 4. Pixels, sea, gap fill, cleanup (FR-589, FR-598, FR-602-604)
Rings convert per view from the raw vertices (section 3); `rasterize` unchanged per view at its own side: main W x W; each inset its own square of side max(rect.w, rect.h), blitted to (x, y); never a full-W raster per inset (1 GiB at 16,384). Layers: land in map order, then one other-land layer (value 0): context features in list order, then the excluded and unselected primary units (never water).
`core/sea.ts` is **not** reused (fused BFS + inline private join: no seam; water stays water; later pixels overwrite). Own pass (`sea-sources.ts`): (1) zones in the FR-605 order, sea territories (code-unit key order) before seeds (list order); sources: a zone's sea units' water pixels and its seed; land wins inside a sea unit; shared pixels to the first zone; (2) pre-BFS reachability pass: label water reachable from the sources, one visit per pixel (~16.8M at the 4,096 fixture, ~268M at the 16,384 guard, untimed); each remaining group one enclosed set (003c); (3) `gapFill` G before zones are assigned (FR-603): a set under G touching land goes whole to the highest-contact territory (ties first in map order), pixels become land, sets reported; (4) BFS through water, ties first in the FR-605 order; remaining sets join the nearest zone (003c FR-162); (5) zero zones: water becomes background, never `no-sea-seeds`. Then the FR-604 min-size check (all at once) and the FR-117/FR-163 cleanup (identity vs `cleanup-direct.ts`).
