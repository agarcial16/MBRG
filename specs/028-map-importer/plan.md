# Plan 028 — Map importer (vector route)
Spec: `spec.md` (approved 2026-11-21, with the OQ5/OQ6 answers). Status: **draft** (presented 2026-11-21, for the strong-tier review and then the user's approval). The importer is a new mode family of the existing `tools/build-map` workspace: it reuses the 003b core **in place, by import** (projection, rasterize, sea, pieces, adjacency, self-check, JSON, PNG check, preview, write), never by copy.

## 2. Curation file, column mapping, selection
`primary` (path relative to the curation file) · optional `context` (≤ 8 paths) · `columns` `{ key, name: 1..3 }` · optional `select`, `exclude` · `params` `{ side 64..16,384, margin 0..0.5, minPieceSize 1..10,000, projection laea|equal-earth, gapFill? 1..10,000 }` · optional `units` (key → `{ name?, kind?: land|sea|exclude, territory?, faction? }`) · optional `territoryBy` `{ property, nameProperty? }`, `territoryNames` · optional `factions` (≤ 9,999 × `{ key, name, color? }`), `factionBy` `{ property, nameProperty? }` · optional `seas` (≤ 1,024 × `{ name, lon, lat }`) · optional `insets` (`{ select, at: [x, y] }`). Unknown members, wrong types, an empty `key`, an over-length list → `invalid-curation` (member path); a curation over 16 MiB fails before parsing (NFR-135). The inspect draft carries every member, an empty `columns.key`, empty lists and the dev parameters (side 2048, margin 0.02, minPieceSize 40, laea), so an unedited draft fails import with `invalid-curation`.
A **unit** = all primary features sharing the usable value (text, or an integer as its shortest decimal) of `columns.key`; its name is the first present `columns.name` value on its first feature, used as given; a disagreement on a name/filter/rule property → `conflicting-unit-property`. A **filter** is `{ property, eq|in|gte|lte }` on usable values (int–int numeric, text–text by code units, text–int never, absent never; ISO date texts compare as dates) or `{ bbox, mode within|intersects }` on the unit's own lon/lat range; `exclude` wins; nothing selected → `empty-selection`; a `units`/`exclude` key naming no unit → `unknown-unit`.

## 3. Projection (FR-600, FR-601)
`laea` reuses `core/projection.ts` untouched: centre = the FR-114 midpoint rule over the selected land units outside every inset; a selected unit vertex more than 90° of great-circle arc from the centre → `selection-too-wide` (unit key); a context or excluded polygon with any vertex beyond 90° is dropped from other land. `equal-earth` is own code, no library: `θ = asin(M·sin lat)`, `M = √3/2`; `F = 1.340264θ − 0.081106θ³ + 0.000893θ⁷ + 0.003796θ⁹`; `D = dF/dθ`; `x = lon·cos θ / (M·D)`, `y = F` (unit sphere: the scale cancels in the frame, as laea); central meridian 0°. The square frame is `frameFor` unchanged. A ring edge with |Δlon| > 180° → `antimeridian-edge` (unit key or context file + feature index). An inset centres its own projection on its units' own lon/lat midpoint (laea; equal-earth: the central meridian only, PD6), rasterizes at the main frame's pixel side, in its rounded-outward margin-expanded projected bbox placed at `(x, y)`; checks `inset-outside-image`, `insets-overlap`, `inset-hides-land`, `unit-in-two-insets`, `empty-inset`; a seed belongs to the first inset that contains it, else the main view.

## 4. Pixels, sea, cleanup (FR-589, FR-598, FR-602 to FR-604)
A **view** maps (lon, lat) → continuous (u, v) (main: `toPixel`; inset: its own frame, offset by `(x, y)`). Rings are converted per view; `rasterize` runs per view **unchanged**: layers are land territories in map order, then other land (context + excluded units) as value 0; FR-602's centre-point rules are exactly `rasterize`'s. The composed image = the main raster with inset rectangles overwritten by their inset rasters. Sea: one zone per sea territory and per `seas` entry; the zone **sources** are the seed pixels plus the water pixels inside sea-unit polygons, in map order; the existing BFS gives ties to the zone first in map order; zero zones are allowed (every water pixel becomes background, never an error); enclosed water joins the nearest zone as 003c. `gapFill` G: each enclosed set of fewer than G pixels that touches a land territory goes, whole, to the land territory with the highest contact count (ties first in map order), **before** the 003c join; without it no water becomes land. Before cleanup, a land or sea territory with no piece of S pixels fails with one `territory-below-min-size` per territory (key, name, pixels, largest piece) in map order; then the FR-117/FR-163 cleanup runs (identity vs `cleanup-direct.ts` still proven).

## 5. Command interface (FR-586, FR-608, FR-610)
`npm run import-map -- extract <shp> --out=<file> [--keep=a,b] [--encoding=utf-8|windows-1252|iso-8859-1] [--round=N≥6]` · `inspect <source> [--draft=<file>]` · `import <curation> --out=<dir> [--preview[=<file>]]`. Exit 0/1/2; one JSON error object per line on stderr with an English `kind`; no network ever (source scan + throwing-fetch tests). Import stage order: usage; output folder (`output-not-empty` before any input is read); curation file; sources; curation checks; projection and insets; pixel steps; self-check (FR-606 = `selfCheck` unchanged) — the first stage with errors stops the run and reports every error of that stage; no file is created, modified or deleted on failure; success writes the three artifacts through the 003b temp+rename rules.

## 6. Decisions (discarded alternative)
- **PD1** One command, three mode words, inside the existing builder workspace (FR-586: "an offline command … with three modes"). Discarded: three scripts (three usage/exit surfaces to keep in sync) and a new workspace (splits the reused core and the pinned manifest tests).
- **PD2** The curation is one hand-edited JSON file (OQ2 A, answered by the spec). Discarded: a guided CLI dialogue (not reviewable or repeatable, and it still needs a file behind it).
- **PD3** Dependencies: **none** (NFR-133). No new third-party package; Equal Earth and SHA-256 are own code; NFR-20 stays at the four 003b areas with `pngjs` and `shapefile` already approved; `@mbrg/protocol` enters `tools/build-map` as a **workspace** dependency (not a library) for `mapDigestBytes` in the stress proof.
- **PD4** Own DBF reader in the scanned core. The shapefile library's DBF path runs `value.trim() || null` (verified in its `dbf/string.js`), which would break FR-590's "nothing else of a value is changed" for leading spaces. Geometry still comes from the library (`openShp`: ring classification kept); DBF bytes are read by our own fixed-width reader (the mirror of `ne-fixture.ts`'s writer), so only trailing space/NUL is stripped and an empty text becomes `null`. The 003b Natural Earth extract keeps the library path unchanged.
- **PD5** The colour assignment of 004 FR-141 (`assignFactionColors`, `directCandidates`) and the 12-colour `PALETTE` move from `apps/web/src/core/{colors,theme}.ts` to `packages/shared`, because FR-607 computes `palette-exhausted` "by the same shared function as the viewer". The viewer files re-export/import them, so every viewer test passes unedited; the shared export pin test is the one pinned test this spec changes besides the ledger (listed in the tasks rules).
- **PD6** An inset re-centres its own projection (FR-601); with `equal-earth` that means the inset's own central meridian, the projection having no centre latitude. The main projection keeps central meridian 0° (FR-600).
- **PD7** `inspect --draft` into a directory that holds a `map.json` (a package folder) is a usage error (`draft-inside-package`), FR-591's "never inside a package folder".
- **PD8** The extract mode keeps record order and never rounds by default (rounding only when asked, ≥ 6 places; the 003b Natural Earth extract sorts and rounds at 5 — it stays exactly as it is, NFR-132).
- **PD9** Curation-given names and colours are validated in the curation stage (`invalid-name`, `invalid-color`, FR-599); source-given names are validated by the self-check (FR-606), and repeated faction names/colours only by the presentation check.
- **PD10** Sizes are checked by `stat` before any read (FR-588, NFR-135) and again on the bytes in the pure core, so a 300 MiB source never enters the heap in a test.

## 7. Test strategy (Vitest)
**Golden thread (FR-611, NFR-132):** the committed `data/importer/dev-map.curation.json` (primary = the committed Natural Earth provinces, context = the committed other land, one territory per province keyed as the grouping table, the five factions with their committed Spanish names, the excluded provinces, the 17 seeds, laea 2048/0.02/40) imports to `map.json` and `presentation.json` **byte-identical to `maps/dev`**, and `ids.png` decoding to the same pixel values; the 003b rebuild test and every 003b test stay green unedited. **Sample (FR-612, NFR-138):** a committed synthetic source + context + curation + expected package (≤ 200 KB primary) exercising a two-feature unit, a `territoryBy` merge, `factionBy` with a per-unit exception, a sea unit + seed, a lake, an inset, a gap fill, an excluded unit and a date-range filter, imported byte for byte; never under `maps/`. **Scale (NFR-136, FR-614):** a deterministic generated fixture (8,132 land units, 52 factions, 59 sea zones, ≥ 5,000,000 positions, side 4,096, S = 8, one inset, one context) imported by the opt-in `scale:import` command **outside `npm test`**, asserting **120 s** and recording time and peak memory in `PROGRESS.md` — a breach stops the milestone and proposes a spec change (as 003b NFR-16); the same fixture at one faction per unit is the stress proof: it loads as the server loads a map (`mapDigestBytes` + `validateMap`) and passes the presentation and id image checks, with the report showing the > 255 factions warning and, when it fails, `palette-exhausted`. Inside `npm test`: a 1,000-unit side-2,048 import (explicit timeout), a 300-faction import (no 255 cap, warning shown) and a 10,000-faction `too-many-factions` before any pixel buffer. **Fixtures (NFR-138):** a Windows-1252 DBF with `.cpg`, a DBF without one, a UTM `.prj`, NUL-padded text, integer keys that lost leading zeros, a `null` geometry, overlapping and gapped polygons, a property on only some features, a world source split at the antimeridian. **Purity (NFR-134):** the scan covers `src/importer/**`; every core runs twice byte-identical while clock and randomness throw. **Language (NFR-137):** literal kind/field/label lists grow per task; the closing task pins them. **Ledger:** `PENDING_028` holds FR-586..FR-614 and NFR-132..NFR-138 (36 ids); T1.1 adds the ranges and updates the size pins.
