## T1.1 Protocol of the ranking read (FR-573 (shape part), FR-565 (cursor and wire parts), FR-563 (row shape part))
- Changed: `packages/protocol/src/wire.ts` (`RANKING_ORDERS`, `RankingOrder`, `RANKING_FIELDS`, `RankingRow`, `RankingAsker` — statistics with an optional `rank` or `{ played: false }`, `RankingPage`, `RANKING_ROW_KEYS`, `RANKING_ASKER_KEYS`, `RANKING_PAGE_KEYS`), `page.ts` (cursor list `ranking`, key `[headFinishedAt, headMatchId, localId]`), `read.ts` (`readRankingRequest`), `encode.ts` (`encodeRankingPage`, row and asker encoders, `won <= played <= scored` checked), `decode.ts` (`readRankingPage`), `index.ts` (exports).
- Plan amendment (cursor key): the approved plan's key `[head, segment, primary, points, playerId]` overflows the 256-character cursor limit at long ids with wide statistics, and a value keyset cannot tell a cursor of one order from another. Amended in `plan.md` (PD3) and `tasks-M1.md` to an identity keyset `[headFinishedAt, headMatchId, localId]`: inside a snapshot the rows, their statistics and every order are frozen (counted matches are immutable and newer ones are excluded by the head bound), so the local id identifies the row's place in any order.

- Pinned tests changed (reason: spec 025 adds a list read): `page.test.ts` (list tags 9 -> 10 with samples for `ranking`), `traceability.test.ts` (ranges add FR-563..FR-572 and NFR-123..NFR-126; 540 -> 554 expected ids; `PENDING_025` with the 14 ids; the 024 exclusion list drops FR-563, FR-572, NFR-123; new pinned test for the 14 ids).

## T1.2 Store reads of the ranking (FR-564 (read part), FR-561 (applied), NFR-125 (store part))
