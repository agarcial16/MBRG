## T2.1 Service ranking read (FR-564 (service part), FR-565 (walk part), FR-567 (service part), NFR-125 (statement-count pin))
- Changed: `apps/server/src/service/matches.ts` (`RankingRequest` beside `HistoryRequest`; `ranking(request)` in the interface and the object: defence in depth first — the namespace as a programming error, the community key `invalid-request ['community']`, the local id `invalid-player-id`, the page size — then one read: a FIRST page takes the snapshot head from `historyAfter(community, namespace, undefined, undefined, 1)` (the newest counted match, even one with no scored results: the shown name may come from it); with a cursor the head is the cursor's `[1],[2]`. `rankingResults` + `rankingNames` bounded by that head, folded with `statsOf` + `shownNameOf`, ordered, ranked and paged with `rankingOf(..., after[3], limit, playerId)`; `next` through `encodeCursor('ranking', [RANKING_ORDERS.indexOf(order), head.finishedAt, head.matchId, next])`.
